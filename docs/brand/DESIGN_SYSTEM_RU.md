# Quattro Formaggi CLI — дизайн-система v1.0

## 1. Идея и состав

Визуальный язык: инструмент инженера — команда, входные данные, проверяемый результат. Основной знак `> qf_` связывает название с реальным CLI `qf`; `>` обозначает ввод, `_` — курсор. Полное имя всегда пишется Quattro Formaggi; qf — сокращение и команда. Четыре части названия не объявляются четырьмя официальными модулями архитектуры.

Пакет содержит чистовую векторную интерпретацию выбранного рендера. Её геометрия и типографика стандартизированы; исходный AI-рендер хранится только как reference. Рабочие логотипы не используют текстуру и свечение. В SVG логотипов символы переведены в контуры, поэтому файл не зависит от установленного шрифта. В шаблонах текст остаётся редактируемым.

## 2. Логотип

Основной lockup: крупное `> qf_` и подпись QUATTRO FORMAGGI. Для маленьких поверхностей используется `>_` в квадрате. Это сокращённая иконка, не самостоятельный уникальный словесный бренд: рядом в интерфейсе или метаданных указывать полное имя.

- dark — знак на тёмном фоне; light — знак на светлом фоне.
- transparent-dark — зелёный и светлый текст без фона, ставить на тёмные поверхности.
- transparent-light — тёмно-зелёный и тёмный текст без фона, ставить на светлые поверхности.
- mono-black / mono-white — одноцветные версии для печати и ограниченных носителей.
- clearspace — не меньше высоты строчной q со всех сторон от видимого знака.
- минимальная ширина полного lockup — 120 px / 30 mm; иконки — 24 px. В очень маленьком размере оставить только иконку.

Не менять интервалы и положение курсора, не растягивать, не наклонять, не добавлять тень, свечение или контур. Команда `$ qf extract` — элемент оформления; она не входит в постоянный логотип. Курсор статичен в статьях и печати. В видео допустимо спокойное мигание с периодом 1200 ms; учитывать reduced motion.

## 3. Цвета

| Токен | HEX | Назначение |
|---|---|---|
| bg | #0B0F0D | Обложки и тёмный режим |
| surface | #151C18 | Карточки и код |
| line | #34473B | Декоративные разделители |
| green | #8FEA83 | Логотип, акцент на тёмном |
| white | #F3F5F0 | Основной текст на тёмном |
| muted | #B4C3B7 | Вторичный текст на тёмном |
| ink | #17241C | Основной текст на светлом |
| paper | #F6F8F4 | Длинная статья и печать |
| darkgreen | #246C30 | Ссылки и акцент на светлом |
| amber | #FFD080 | Ограничение / гипотеза на тёмном |
| red | #FF9C9C | Ошибка на тёмном |

Зелёный не означает автоматически «верный результат»: статусы сопровождаются текстом. Amber/red в этой таблице предназначены для тёмной поверхности; для светлой используйте #7A4B00 / #9B2525. line — декоративный токен, а не цвет текста или единственная граница активного элемента. Графики различать также подписями, типом линии и штриховкой.

Обложки: ориентир 80% нейтрального фона, 15% текста, 5% акцента. Длинные материалы: светлый фон и тёмный текст; тёмные блоки только для кода и коротких выводов.

## 4. Типографика

Фиксированный набор без сетевой загрузки: DejaVu Sans Mono для логотипа, заголовков, команд и данных; DejaVu Sans для основного текста. Regular и Bold приложены вместе с условиями использования. Оба поддерживают кириллицу. В CSS сначала локальные имена, затем monospace/sans-serif.

| Элемент | Веб | PDF A4 | Правило |
|---|---:|---:|---|
| H1 | 40 px | 27 pt | Не более 3 строк |
| H2 | 28 px | 18 pt | Одна мысль |
| H3 | 20 px | 13 pt | Короткий подзаголовок |
| Текст | 18 px / 1.6 | 10.5–11 pt / 1.45 | 60–75 символов в строке |
| Код | 16 px / 1.5 | 9.5 pt | Отдельный блок |
| Подпись | 14 px / 1.5 | 8.5–9 pt | Источник и ограничения |

Крупные числа использовать только вместе с названием метрики и знаменателем. Моноширинный шрифт не применять ко всему длинному тексту. Не добавлять псевдокод ради украшения. В обложках 1080–1600 px заголовки ориентировочно 50–80 px; перед экспортом проверить переносы.

## 5. Сетка и отступы

Базовый шаг — 8 px; набор 4/8/12/16/24/32/48/64/96. Радиус карточки 12 px. Обложки: поля 6.5% ширины, логотип сверху, рубрика под ним, заголовок в средней части, источник внизу. Для A4 поля не меньше 18 mm; основной текст — одна колонка. Для отчётов допустима таблица на всю ширину.

| Носитель | Размер шаблона | Применение |
|---|---|---|
| Обложка статьи | 1600 × 900 | Блог, технический материал |
| Горизонтальный анонс | 1200 × 627 | Социальная публикация |
| Квадрат | 1080 × 1080 | Тезис, цитата автора с атрибуцией |
| Портрет | 1080 × 1350 | Карточка результатов / карусель |

Это рабочие размеры пакета, не утверждение об обязательных требованиях конкретной платформы. Перед загрузкой проверить актуальное кадрирование в её preview. Если текст выходит за поля, сократить заголовок или перенести строку; не уменьшать весь текст до нечитаемого размера.

## 6. Компоненты материала

1. Терминальная рубрика: RESEARCH NOTES, PROJECT UPDATE или BASELINE.
2. Заголовок: деловая мысль человеческим языком, без служебных префиксов.
3. Код: только настоящая команда; пример `$ qf extract` не обещает конкретную синтаксическую форму остальных аргументов.
4. Статус: «подтверждено», «гипотеза», «план»; текст + цвет.
5. Результат: метрика → значение → режим → набор и n → источник.
6. Ограничение: короткий отдельный абзац рядом с числом.
7. CTA: один вопрос или один следующий шаг.

## 7. Структура статьи

Проблема процесса → конкретный пример заявки → исследовательский вопрос → сравниваемые решения → данные и методы → результаты → типы ошибок → ограничения → следующие эксперименты.

Минимум к таблице: метрика, режим модели, benchmark, размер/знаменатель, дата, источник, CI если он есть. Не рисовать доверительные интервалы, которых нет в исходном отчёте. Нельзя менять определение метрики между выпусками без заметного объяснения.

В статьях разбираем решения и данные. В коммерческих материалах описываем сценарий пилота и критерии пользы; ожидаемую выгоду не заменяем придуманным процентом ROI. В научных материалах сокращаем брендовый декор: светлый фон, подписи рисунков, полные ссылки и методика.

## 8. Иллюстрации и диаграммы

Предпочтительны схемы процесса, карточки, таблицы ошибок, реальные обезличенные примеры и графики с подписями. Тонкие линии, простые блоки, минимум декоративных узлов. Не использовать нейросетевые мозги и роботов как основную метафору. Синтетический пример подписывать «демонстрационный»; мок — «имитированный». Цветные статусные плашки не заменяют проверку результата.

## 9. Голос бренда

Спокойно, конкретно, от лица практика. Формула: задача → метод → измерение → ограничение → следующий шаг. «Исходная модель показала…» вместо «Наш AI гарантирует…». «Проверим на реальных примерах» вместо «Готово к любому бизнесу». Допустимо рассказывать об ошибках: они помогают читателю понять, что именно проверяется.

RU: короткие предложения, знакомые логистические термины с пояснениями. EN: clear professional English, avoid inflated claims. Не выдавать предложенный слоган за личную цитату автора.

## 10. Экспорт и передача

SVG — мастер для масштабирования, PNG — готовый растровый файл; прозрачные PNG имеют alpha. Стандарт sRGB. Для печати согласовать цветопробу с типографией, не конвертировать автоматически HEX в обещанный Pantone. Логотипы — контуры; шаблоны требуют установки приложенных шрифтов. Для веба можно подключить приложенные TTF через @font-face либо оставить системные fallback.

Файлы: qf-{носитель}-{тема}-{язык}-{дата}-v{версия}. Например qf-cover-baseline-ru-20260930-v1.png. Архив v1 содержит четыре редактируемых SVG и их PNG, набор логотипов, токены, шаблон HTML-статьи, пресс-тексты и этот регламент.

## 11. Контроль перед публикацией

Название и текущий статус верны; цифры совпадают с отчётом; режим и знаменатель указаны; ограничения видны; планы отделены от результатов; контакты заполнены; нет внутренних журналов или персональных данных; заголовок читается на телефоне; логотип не искажён; внешние ссылки проверены автором.
