# DECISIONS.md — журнал решений

Каждое решение: ID, суть, причина, шаг, где принято. Замена компонента оформляется новой записью (ADR) по процедуре C.9 `docs/ARCHITECTURE.md`.

## Базовые решения (таблица B.4 `IMPLEMENTATION_PLAN.md`)

| ID | Решение | Причина |
|---|---|---|
| D-001 | Менеджер окружения `uv`, lockfile `uv.lock`, Python 3.11 | Воспроизводимость, быстрая установка extras |
| D-002 | CLI на `argparse` (stdlib) | Меньше зависимостей, простая тестируемость |
| D-003 | Обучение через `transformers.Trainer` + `peft` с собственной маской loss. TRL не используется | Полный контроль над assistant-only loss (§10 плана разработки: маску нужно проверить, а не доверять флагу). Один training backend |
| D-004 | Модель выдаёт массу «как в тексте» (value + unit), а пересчёт делает код | Модель не занимается арифметикой. Ошибки единиц ловит валидатор |
| D-005 | Gold выводится из строк датасета и из фактически отрендеренного текста | Эталон не зависит от LLM и человека. Проверяемо тестами |
| D-006 | Split по `group_id` плюс отдельные holdout-маршруты и holdout-семейства шаблонов для `test_ood` | Шаблонные данные легко запоминаются. Без OOD-теста метрика измерит запоминание шаблонов |
| D-007 | Один системный промпт `system_extract_v1` на русском для всех записей; runtime использует тот же файл | Одинаковые условия train, eval и runtime; хэш промпта в манифесте |
| D-008 | Перефразирование через LLM в v0.1 выключено | Шаблоны детерминированы и проверяемы. Опция описана в шаге 6.8 |
| D-009 | Слоистая архитектура «порты и адаптеры», правила импорта проверяет `import-linter` | Замена компонента не ломает остальные (Часть C) |
| D-010 | Стадии обмениваются только артефактами с манифестом (`ArtifactRef`) | Любую стадию можно переписать, сохранив контракт артефакта |
| D-011 | Реализации выбираются по имени из реестра через YAML-конфиг; тяжёлые — лениво | Переключение без правки кода; лёгкие части работают без CUDA-стека |

## Решения шага 1 (23.09.2026)

| ID | Решение | Причина |

| D-012 | `mypy --strict` включён **глобально** для всего пакета `qf` (`[tool.mypy] strict = true`), а не только для перечисленных в шаге 1 пакетов | `strict` в mypy — только глобальная опция, в `[[tool.mypy.overrides]]` её задать нельзя. Глобальный режим — надмножество требования плана. | D-013 | `torch` в `qf.common` импортируется только по имени во время выполнения (`qf.common._optional.import_optional`), ровно в двух местах: `common/doctor.py` и `common/seed.py` | Контракт import-linter запрещает `qf.common → torch`; `seed.py` обязан сидировать torch, если он установлен. Динамический импорт не виден статическому анализу, поэтому набор мест ограничен и помечен комментариями. Текст C.3 плана обновлён |

| D-015 | Команда оценки — `qf eval run`, а не `qf eval` | Имя не может быть одновременно командой и группой (`qf eval compare`): argparse трактует позиционный аргумент `qf eval …` как подкоманду, и нереализованная команда давала ошибку разбора вместо «not implemented». | D-017 | Нереализованные команды принимают любые аргументы (разбор через `parse_known_args`) и всегда завершаются кодом 2 с сообщением `Stage <N> is not implemented yet`; реализованные команды с неизвестными аргументами — ошибка использования (тоже код 2, но с `unrecognized arguments`) | Код 2 у argparse означает ошибку использования — чтобы коды не путались, тесты проверяют и код, и текст stderr |
| D-018 | `qf doctor` не использует `system_profiler`: только `platform`, `psutil`, `shutil` | В отчёт не должны попадать серийный номер и UUID машины |
| D-019 | Во все форматы на диске добавлено поле версии: `RunManifest.manifest_version = "run_manifest_v1"`, `ArtifactManifest.artifact_manifest_version = "artifact_manifest_v1"`, отчёт doctor `report_version = "doctor_v1"` | Правило C.7: формат манифестов версионируется; при изменении формата — новая версия, а не правка старой |
| D-020 | `atomic_write_text` выставляет записанному файлу права `0644` | `tempfile.mkstemp` создаёт файлы `0600`; без этого артефакты и отчёты были бы нечитаемы для других пользователей и инструментов |
| D-021 | `cli.wiring.build()` получает `Config` реализации, импортируя саму реализацию. Хранение в ленивой записи реестра отдельного пути к лёгкому модулю `Config` (C.5) **не реализовано** | На шаге 1 реализаций нет. Понадобится на шаге 12, если `qf train estimate` или валидация конфига обучения должны работать на Mac без torch: тогда добавить в `register_lazy` параметр пути к `Config` |

## Решения шага 4 (23.09.2026)

| ID | Решение | Причина |
|---|---|---|
| D-041 | Модели контрактов `card_v1` и `sft_record_v1` строгие: общий базовый класс `ContractModel` (`extra="forbid"`, `frozen=True`, `strict=True`, `allow_inf_nan=False`). Такой ответ модели засчитывался бы как валидный и скрывал ошибки в `json_valid_rate` (§6 плана разработки: валидный JSON не доказывает правильность значений) |

При `weight_per_piece` без `pieces` в списке только `pieces`. Текст B.3 исправлен | Формулировка B.3 («иначе добавляется `weight_total`») противоречила обязательному тесту шага 4 `test_per_piece_without_pieces_missing_pieces_only` (`missing == ["pieces"]`). ## Российские города вместо американских (23.09.2026, по решению автора проекта)

| ID | Решение | Причина |
|---|---|---|
| D-047 | Модель работает с **российскими** городами. Сырой датасет не меняется (provenance, `qf data profile` и `expectations.yaml` по-прежнему проверяют американские города); на шаге 5 каждый из 20 городов источника заменяется одним из 20 российских по фиксированной версионируемой таблице `configs/data/city_map_ru_v1.yaml` (`qf.data.CityMap`), её хэш пишется в манифест. Набор: все 16 городов-миллионников плюс Тула, Томск, Кемерово, Барнаул. Соответствие подобрано локальным поиском по 30 кандидатам (миллионники обязательны): минимум суммы квадратов логарифма отношения «расстояние по прямой × 1,2» к дорожному расстоянию источника по 58 маршрутам. Итог: корреляция 0,94, медианное отклонение 16%, худшее 43% (`tests/test_city_map.py` требует > 0,9 и < 20%). Таблица — зафиксированные и проверенные данные, а не воспроизводимый результат скрипта: поиск зависел от порядка перебора, и его скрипт в репозиторий не входит; качество таблицы охраняет тест. Расстояние в тексте заявок не пишется; hard case `ru_city_names` заменён на `city_lang_switch`. Эта запись заменяет городскую часть B.1, B.3 и `docs/PROJECT.md` §3; план разработки американских городов не упоминал | Решение автора проекта: модель работает в российской логистической компании.
